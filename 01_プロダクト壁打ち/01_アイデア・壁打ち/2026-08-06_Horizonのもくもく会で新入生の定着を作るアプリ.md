# 壁打ちメモ｜Horizonのもくもく会で「できた」を持ち帰れるようにするアプリ

更新日：2026年8月6日  
ステータス：AI Builders Camp 京都Kick Off の本命案  
団体：プログラミングサークル Horizon（週1の対面もくもく会が活動の中心）

## この案に切り替えた理由

AICampのお題は「自分たちの団体が抱える課題を解決するプロダクトを作れ」である。
[前案](./2026-08-05_初対面の学生を再会につなげるアプリ.md)は大学生全般の新歓を対象にしていたため、
「自分たちの団体の課題」という前提から外れていた。

そこで、前案の骨格をそのままHorizonの中へ移植した。

| 前案（大学生全般） | 本案（Horizon内） |
| --- | --- |
| 新歓で交換した相手を思い出せない | 入会した1年生がもくもく会に来なくなる |
| 出会いカード（出会った場面・共通点） | メンバーカード（得意／学習中／今つくっているもの） |
| 共通授業・空きコマ | 共通の技術・今日やること・詰まっているところ |
| 大学イベントの参加表明 | 今日のもくもく会の参加表明 |
| AIが「一緒にできること」と誘い文を提案 | AIが「今日のゴール」「今日の相棒」「声のかけ方」を提案 |
| 予定が成立して二回目が起きる | 「できた」が1つ残って、翌週また来る |

変わったのは対象と語彙だけで、**「散らばった情報から、次の具体的な行動を作る」という中心の仕組みは同じ**。

## どんな課題があるのか

新歓でHorizonに入会した1年生が、週1の対面もくもく会に数回来たあと、来なくなる。

初参加の日の実際の流れ：

1. 席に座ってPCを開く
2. 今日やることが決まっていないので、まず入門記事を検索するところから始める
3. 環境構築やインストールでつまずき、エラー文を検索し続ける
4. 周りは各自の作業に入っていて、声をかけるタイミングが分からない
5. 2時間経って、動くものは何もできないまま帰る
6. これが2〜3回続くと、次の週から来ない

中心課題は、**もくもく会に来た時点で「今日の2時間で終わるゴール」が決まっておらず、手応えゼロのまま帰ること**。

## 最初に想定するユーザーと場面

### ユーザー

- Horizonに入会して3か月以内の1年生（特にプログラミング未経験・初心者）
- あわせて、誰が離脱しかけているか分からないまま人数が減っていく運営メンバー

### 利用場面

- 週1の対面もくもく会の冒頭5分（今日やることを決めるとき）
- 会の途中（詰まって、誰かに聞きたいとき）
- 終了5分前（今日できたことを残すとき）

## その案はどんな案なのか

もくもく会の冒頭に、全員が「今日やること」を1行だけ宣言する。
AIがその場の参加者全員の宣言と得意分野を突き合わせて、次の3つを返す。

1. **今日のゴール**：宣言を2時間で終わるサイズに刻み直したもの
2. **今日の相棒**：今日の参加者の中で、詰まったときに聞くといい人
3. **声のかけ方**：その人に話しかけるための1文

終了5分前に「できたこと」を1行だけ記録する。それが次回の冒頭に「前回できたこと」として出てくる。

### 体験フロー

```text
参加表明 → 今日やることを1行宣言 → AIがゴール・相棒・声のかけ方を出す
  → 2時間作業する → 「できた」を1行記録 → 次回の冒頭に持ち越される
```

## それでどんなDelightが生まれるのか

Delightは「便利になる」ことではなく、**想像を超える喜び**である。この案でのDelightは次の瞬間に置く。

- 初めて来た日に、自分の手で動くものが1つできて、それを誰かが見てくれる
- 「聞いていいのかな」と迷っていた相手から、先に「それ、自分もやったよ」と返ってくる
- 3か月後、「できた」の1行が積み上がって、自分がどれだけ進んだかが目に見える
- 教える側にも「誰かの役に立った記録」が残る
- 運営が、来なくなりそうな人に、来なくなる前に気づける

「出席率が上がる」はDelightではなく結果指標。狙うのは、**帰り道に「今日、できた」と言える状態**。

## AIを使う場所

出席管理も、宣言の掲示も、AIなしでできる。AIを使う意味は次の2点に置く。

1. **サイズの調整**：「Reactをやってみたい」という粒度の宣言を、
   「Viteでプロジェクトを作って、ボタンを押すと数字が増えるところまで」という2時間サイズに刻み直す。
   これは相手のレベルと残り時間に依存するので、固定のルールでは書けない。
2. **その場の人との突き合わせ**：今日その場に誰がいて、誰が何を得意としていて、
   誰が同じところで詰まったことがあるかを見て、相棒と声のかけ方を出す。
   参加者の顔ぶれは毎週変わるので、事前に作った対応表では機能しない。

表示例：

> 今日のゴール：Viteでプロジェクトを作って、ボタンを押すと数字が増える画面まで  
> 今日の相棒：タクミさん（先月Next.jsで同じ環境構築をやっている）  
> 声のかけ方：「環境構築でつまずいたら聞いてもいいですか」

## 他の手段との違い

| 既存の手段 | できていること | 残る原因 |
| --- | --- | --- |
| Discordの告知 | 来るきっかけを作る | 来たあとの2時間に関与しない |
| 入門資料の共有 | 読む材料を渡す | 読むだけで手が動かず、その日の成果にならない |
| 先輩の声かけ | 気づけた人は救われる | 黙って詰まっている人には届かない |
| Notion・スプレッドシートの出席簿 | 記録は残る | 記録から次の行動が生まれない |
| ChatGPT | ゴールの分解はできる | 今日その場に誰がいるかを知らないので相棒を出せない |
| connpass等 | 告知と出席管理 | 会の中身には踏み込まない |

つまり、**「その日その場にいる人の宣言と得意分野を突き合わせて、2時間で終わるゴールと聞ける相手を同時に出す」役を、今は誰も担っていない**。

## 成功の定義

### 最重要指標

**もくもく会に来た人のうち、「できた」を1つ持ち帰った人の割合。**

### 補助指標

- 「できた」を残した人の、翌週の再参加率
- 相棒の提案から実際に会話が発生した割合
- 新歓入会者の3か月後の継続率（最終的に効かせたいのはここ）
- 教える側が「聞かれた」回数

## 懸念・疑問

- 宣言を書くこと自体が面倒だと感じられたら、その時点で止まる。1行・5秒で終わる設計にできるか
- AIが刻んだゴールが的外れだと、逆に「分かってない」と感じさせる
- 相棒の提案が、教える側の負担になったり、断りにくい空気を生んだりしないか
- 人数が少ない日は、相棒として指せる人がいない
- 「できた」が書けなかった日に、書けなかったこと自体が責めになって見えないか
- 運営が離脱を把握できることを、監視だと受け取られないか

## プライバシー・空気の設計

- 「できた」の記録は本人が書いたものだけを表示し、書かない自由を残す
- 相棒の提案は「聞いてもいい人」であって、義務ではない。教える側にも断る導線を置く
- 詰まっていることを晒す形にしない。宣言はあくまで「今日やること」であって進捗報告ではない
- 出席の記録は運営が見るが、「来ていない人リスト」のような形では出さない
- AIは本人の確認なしにメッセージを送らない

## 未決事項

1. プロダクト名（第1候補：できた／Dekita、他：もくもくバディ、Horizon Today）
2. 宣言は毎回書かせるか、前回の続きをデフォルトにするか
3. 相棒は1人に絞るか、複数候補を出すか
4. 「できた」が書けなかった日をどう扱うか
5. 得意分野の登録を、初回に入力させるか、宣言の履歴から自動で推定するか
6. 運営向けの可視化を、どの段階から入れるか

## 次に検証すること

- 新歓入会者のうち、今も来ているのは何人か（出席の実数）
- 来なくなった1年生に、最後に来た日に何をしたか・何かできた実感があったかを聞く
- 「今日やること」を1行書くことに抵抗があるか
- AIが刻んだゴールが、実際に2時間で終わるサイズになっているか
- 相棒を提案されたとき、実際に声をかけられるか
