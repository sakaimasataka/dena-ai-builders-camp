# MVP要件定義｜初対面の学生を再会につなげるアプリ

作成日：2026年8月5日  
用途：AI Builders Camp 京都Kick Offでのモック制作・要件共有  
状態：初版。未決事項は末尾に明記する。

## 1. プロダクト概要

### 一言で表すと

> 新歓や授業で出会った大学生同士が、互いのプロフィール、時間割、参加イベントから共通点を見つけ、次に一緒に行動する予定を作れるアプリ。

### 最終目標

大学生が初対面の相手と連絡先を交換するだけで終わらず、その人を思い出し、予定を合わせ、実際に一緒に行動できる状態を作る。

### 解決したい課題

- 新歓や4月最初の授業でInstagramやLINEを交換しても、後から相手が誰だったか分からなくなる
- もう一度話したい相手がいても、自然に連絡する理由や機会がない
- 友達や知り合いと授業・空きコマ・イベント予定を合わせるのが面倒
- 大学独自のイベント情報と、知り合いの参加予定が別々に存在している

### 提供価値

1. **思い出せる**：誰と、どこで出会ったかが残る
2. **共通点が分かる**：同じ授業、サークル、興味、イベントが分かる
3. **予定を合わせられる**：本人が公開した時間割を見て、会う候補を考えられる
4. **行動に移せる**：AIが一緒にできることと誘い方を提案する

## 2. 想定ユーザー

### 最初の対象

- 入学直後の4月、大学内で友達や知り合いを増やしたい新入生

### 最初の利用場面

- サークルの新歓
- 4月最初の授業
- オリエンテーションや大学イベント

### 継続利用する場面

- 友達の時間割を見て、空きコマに誘う
- 同じ授業を取っている人を確認する
- 大学イベントに誰が参加するか確認する
- サークル予定や自分の参加予定を共有する

## 3. 成功の定義

### 最重要指標

**QR交換数ではなく、アプリを通じて成立した共同予定の数。**

モック段階では、ユーザーが次の一連の操作を迷わず完了できれば成功とする。

> QR交換 → 相手と出会った文脈を確認 → 共通点・時間割を確認 → AI提案を見る → 一緒に行動する予定を提案

### 補助指標

- QR交換から予定提案までの到達率
- 予定提案の承認率
- 交換した相手の詳細画面を再訪した割合
- 共通授業または共通イベントが見つかった割合
- 1週間あたりの共同予定成立数

## 4. MVPで証明する仮説

> 初対面で交換した相手との共通点と次に会える機会が自動で示されれば、大学生はInstagramだけを交換した場合より、二回目の行動を起こしやすい。

MVPで証明したいのは、完成した予定管理サービスではない。**初対面の相手との情報が、具体的な次の行動へ変わる体験**である。

## 5. MVPの基本方針

- スマートフォンで使うWebアプリまたはアプリ風モックとする
- QR交換の瞬間には、追加のメモ入力を要求しない
- 何もしなくても、交換日時・出会った場面・共通情報が残る
- 時間割を表示するかどうかは本人が決める
- MVPでは「誘われてもよい時間」の設定や高度な自動調整は行わない
- AIは予定を決定せず、共通点、行動候補、誘い文を提案する
- モックでは一つの固定シナリオを最後まで体験できることを優先する

## 6. MVPの利用シナリオ

### デモ用シナリオ

1. 新入生のユーザーAが、軽音サークルの新歓でユーザーBと会う
2. AがBのQRコードを読み取る
3. Bの「出会いカード」が作成され、「軽音サークル新歓で交換」と表示される
4. 二人が同じ「心理学概論」を履修していることが強調表示される
5. Bが時間割を公開しているため、AはBの時間割を確認できる
6. 大学イベント「新入生交流会」に二人とも参加予定であることが分かる
7. AIが「心理学概論の授業後に学食へ行く」案と誘い文を提案する
8. Aが内容を確認し、Bへ予定を提案する
9. Bが承認すると、共同予定として表示される

## 7. 機能要件

優先度：P0＝MVP必須、P1＝余裕があればモックに含める、P2＝将来機能。

| --- | --- | --- |

| PR-03 | P0 | 自分のプロフィール交換用QRコードを表示できる |
| PR-04 | P1 | InstagramまたはLINEへのリンクを登録できる |

### 7.2 QR交換・出会いカード

| ID | 優先度 | 要件 |
| --- | --- | --- |
| CN-01 | P0 | 相手のQRコードを読み取ってつながれる |
| CN-02 | P0 | 交換した相手が「出会いカード」として一覧に追加される |
| CN-03 | P0 | 交換日時と出会ったイベントまたは授業を表示できる |
| CN-04 | P0 | 二人の共通プロフィール、共通授業、共通イベントを強調表示する |
| CN-05 | P1 | 出会った場面を自動推定できない場合、候補から1タップで選べる |
| CN-06 | P1 | ユーザーだけが見られる任意メモを追加できる |

### 7.3 時間割

| ID | 優先度 | 要件 |
| --- | --- | --- |
| TT-01 | P0 | 曜日・時限ごとに授業名を登録できる |

| TT-03 | P0 | 時間割を相手に表示するか、本人が選択できる |
| TT-04 | P0 | 公開している相手の時間割をプロフィールから確認できる |
| TT-05 | P0 | 二人が同じ授業を取っている場合、共通授業として表示する |
| TT-06 | P1 | 二人の時間割から共通する空きコマを表示する |
| TT-07 | P2 | 公開範囲を「全員」「つながった人」「選んだ人」などに細分化できる |
| TT-08 | P2 | 「この時間は誘われてもよい」を設定できる |
| TT-09 | P2 | 複数人の予定を自動調整できる |

### 7.4 大学イベント・個人予定

| ID | 優先度 | 要件 |
| --- | --- | --- |
| EV-01 | P0 | 大学独自のイベントを時間割・カレンダー上に表示する |
| EV-02 | P0 | 未参加のイベントは灰色で表示する |
| EV-03 | P0 | 「参加する」を選ぶとイベントに色が付く |
| EV-04 | P0 | つながった相手のうち、同じイベントへの参加予定者を確認できる |
| EV-05 | P1 | 自分の予定やサークル予定を追加できる |
| EV-06 | P1 | 追加した予定を公開するか選択できる |
| EV-07 | P2 | 大学の公式システムやイベント情報から予定を自動取得する |

### 7.5 AIによる提案

| ID | 優先度 | 要件 |
| --- | --- | --- |
| AI-01 | P0 | 二人の共通授業、共通イベント、プロフィール上の共通点を短く整理する |
| AI-02 | P0 | 利用可能な情報から、二人で一緒にできる行動を1〜3件提案する |
| AI-03 | P0 | 選んだ行動に対して、自然な誘い文を生成する |
| AI-04 | P0 | 提案に使った根拠を「同じ授業」「同じイベント」などの形で表示する |
| AI-05 | P0 | 非公開の時間割や予定を、相手への表示・提案文で漏らさない |
| AI-06 | P1 | 提案の雰囲気を「気軽」「丁寧」などから選べる |
| AI-07 | P2 | 過去の承認・拒否を学習し、提案内容や通知頻度を個人化する |

### 7.6 予定の提案・成立

| ID | 優先度 | 要件 |
| --- | --- | --- |
| PL-01 | P0 | AIの行動提案を確認・編集できる |
| PL-02 | P0 | 日時、内容、相手を指定して予定を提案できる |
| PL-03 | P0 | 相手が予定を承認または辞退できる |
| PL-04 | P0 | 承認された予定を「一緒にする予定」として表示する |
| PL-05 | P1 | InstagramやLINEへ誘い文を共有できる |
| PL-06 | P1 | 予定前に通知できる |

## 8. 画面要件

### 明日のモックで必須の5画面

1. **ホーム／時間割画面**  
   自分の授業、灰色の大学イベント、参加表明した色付きイベントを表示する。

2. **QR交換画面**  
   自分のQR表示と、相手のQR読み取りを体験できる。

3. **交換完了／出会いカード画面**  
   相手のプロフィール、出会った場面、共通点を表示する。

4. **AI提案画面**  
   共通授業・イベント・公開時間割を根拠に、行動候補と誘い文を表示する。

5. **予定提案・成立画面**  
   日時と内容を確認して送り、相手が承認した状態まで見せる。

### 補助画面

- プロフィール登録・編集
- 時間割登録・公開設定
- つながった人の一覧
- 大学イベント詳細

補助画面は静的表示でもよく、デモでは必須5画面を優先する。

## 9. AIへの入力と出力

### 入力データ

- 自分と相手の公開プロフィール
- 共通授業
- 相手が公開している時間割
- 互いが参加表明したイベント
- ユーザーが選んだ相手と希望日時

### 出力例

```text
共通点
・心理学概論を一緒に履修
・軽音サークルに興味あり
・新入生交流会に参加予定

おすすめ
心理学概論が終わったあと、一緒に学食へ行く

誘い文
「この前の軽音新歓で話した〇〇です！ 次の心理学概論のあと、よかったら一緒に学食行かない？」

提案の理由
同じ授業と参加予定イベントがあるため
```

### AIがしてはいけないこと

- 非公開情報を相手に示す
- 確認できない共通点や予定を作る
- ユーザーの承認なしで予定やメッセージを送る
- 恋愛関係など、本人が示していない関係性を決めつける
- 会話を無断で録音・解析する

## 10. プライバシー要件

- 時間割を公開するかどうかは本人が決める
- MVPでは、時間割の表示・非表示を分かりやすく切り替えられるようにする
- 非公開情報は相手の画面にも、AIの提案理由にも表示しない
- イベント参加予定と個人予定も、公開する情報を本人が管理する
- 自分用メモは相手に表示しない
- ブロック、つながり解除、通報は本実装で必須とし、モックでは存在を示す

## 11. 非機能要件

- スマートフォン縦画面を基準にする
- QR交換からAI提案の確認まで、目標60秒以内とする
- 主要操作は片手で完了できる大きさ・配置にする
- 重要な公開設定は、現在の状態が一目で分かるようにする
- 灰色と色付きの違いだけに依存せず、文字やアイコンでも参加状態を示す
- AI提案中であることと、事実として登録された情報を区別して表示する
- モックでは固定データを利用し、通信障害や生成待ちによるデモ失敗を避ける

## 12. MVPの対象外

次の機能は構想には残すが、明日のモックの必須範囲には含めない。

- 「誘われてもよい時間」の設定
- 複数人の時間割を使った高度な自動調整
- 現在地の共有
- 会話の録音・自動文字起こし
- AIによる完全自動メッセージ送信
- 大学公式システムとの実接続
- 厳密な本人確認・大学認証
- 決済、予約、チケット購入
- 詳細な通知頻度の個人最適化

## 13. 受け入れ条件

MVPは次をすべて満たしたとき、デモ可能と判断する。

- [ ] QRを読み取ると、指定した相手の出会いカードが表示される
- [ ] 出会った場面とプロフィールが確認できる
- [ ] 共通授業または共通イベントが一つ以上表示される
- [ ] 相手の時間割が公開設定の場合のみ表示される
- [ ] 大学イベントの未参加・参加予定が見分けられる
- [ ] AIが共通情報を根拠に行動候補と誘い文を提示する
- [ ] ユーザーが提案内容を確認してから送れる
- [ ] 相手の承認後、共同予定として表示される
- [ ] 非公開情報が相手側の画面や提案文に出ない
- [ ] 一連のデモを3分のピッチ内で完了できる

## 14. 競合との差別化仮説

時間割管理や時間割共有だけでは、既存の大学生向けアプリとの差別化にならない。本プロダクトは次の一本の流れを差別化仮説とする。

> 現実の場でQR交換した相手について、出会った文脈と大学生活上の共通点を残し、AIが次の共同行動へ変換する。
