# MVP要件定義｜同じサークルなのに、まだ話したことがない人と最初の1回をつくるアプリ

作成日：2026年8月6日  
用途：AI Builders Camp 京都Kick Off でのモック制作・要件共有  
団体：プログラミングサークル Horizon（龍谷大学・瀬田／深草）

## 1. プロダクト概要

### 一言で表すと

> 同じサークルなのに、まだ一度も話したことがない人との最初の1回をつくるアプリ。

### 解決したい課題（ワークシートStep2〜4と同じ）

Horizonの新入部員と既存部員が、普段の活動やイベントの際にお互いの情報を認識できておらず、
コミュニケーションが不足して、関係が希薄なまま固定されている。
特に瀬田と深草の2拠点に分かれているため、別キャンパスのメンバーとは
名前を知っているだけで一度も話したことがない状態が起きやすい。

今日解消する原因（Step4で1つに絞った）：
**相手が今何をやっているかが見えないので、共通点が分からず、話しかける材料がない。**
DiscordもイベントもSNSも「場所」を用意しているだけで、誰と誰が話すべきかを指していない。

> 対象はHorizonの部員のみ。大学全体・他サークルの学生は対象にしない。

### 提供価値

1. **相手が見える**：キャンパス・今つくっているもの・得意・詰まっていることが分かる
2. **相手が決まる**：まだ話していない人の中から、共通点を根拠に1人が出る
3. **一言目がある**：そのまま送れる最初のメッセージが生成される
4. **距離が消える**：接点はオンラインで完結するサイズに限定される

## 2. 想定ユーザー

### 主ユーザー

- Horizonの部員全員（大学全体ではなく、サークル内に閉じる）
- 特に、入会したばかりでまだ誰にも認識されていない新入部員と、
  自分の拠点に同じ興味の人がいない部員

### 副ユーザー

- 拠点をまたいだ企画が組めずにいる運営メンバー

### 利用場面

| タイミング | すること |
| --- | --- |
| カードを更新したとき | 今つくっているもの・詰まっていることを1行書く |
| 週に1回 | 「今日の一人」を見て、一言目を送る |
| やりとりのあと | 「話した」を記録する |

## 3. 成功の定義

### 最重要指標

**部内で「話したことがある人」の数の増加。** 特に新入部員×既存部員、別キャンパス同士の初回接触数。

モック段階では、次を迷わず完了できれば成功とする。

> メンバーボードを見る → 今日の一人が出る → 共通点と根拠を確認する → 一言目を確認して送る → 「話した」を記録する

### 補助指標

- 提案された相手に実際に一言目を送った割合
- 送った一言目に返信が来た割合
- カードを更新した人の割合
- Discordで発言する人の顔ぶれの広がり

## 4. MVPで証明する仮説

> まだ話したことがない相手について、共通点と一言目が用意されていれば、
> キャンパスが離れていても、サークル内で新しい接点が実際に生まれる。

## 5. MVPの基本方針

- スマートフォン縦画面で使うWebアプリとする
- カードの入力は各項目1行。空欄を許す
- AIは相手を決定せず、1人を提案する。送るかどうかは本人が決める
- 一言目はAIが送らない。本人が確認・編集してから使う
- 提案する接点は、オンラインで完結するサイズに限定する
- 相性スコア・ランキングを出さない（マッチングアプリに見せない）
- モックでは固定データを使い、生成待ちや通信でデモが止まらないようにする

## 6. デモ用シナリオ

1. 瀬田キャンパスの1年生ユーザーAが、自分のカードの「今詰まっていること」に
   「Viteの環境構築でエラーが出る」と書く
2. メンバーボードには、瀬田・深草のメンバーが並んでいる。
   Aが話したことがあるのは同じ瀬田の2人だけで、他はグレー表示になっている
3. 「今日の一人」を開くと、深草キャンパスのタクミさん（3年）が出る
4. 共通点と根拠が表示される
   → 「あなたが詰まっているVite環境構築を、先月同じ構成でやっている」
5. 今日できる接点が出る
   → 「30分だけ画面共有して、エラーを一緒に見てもらう」
6. 一言目が出る
   → 「はじめまして、瀬田の〇〇です。Viteの環境構築で詰まっていて、
     同じ構成をやられていたので、30分だけ見てもらえませんか」
7. Aが内容を確認して送る
8. やりとりのあと「話した」を記録すると、タクミさんのカードに色が付き、
   「話したことがある人：3人 → 4人」に増える

## 7. 機能要件

優先度：P0＝MVP必須、P1＝余裕があれば、P2＝将来。

### 7.1 メンバーカード

| ID | 優先度 | 要件 |
| --- | --- | --- |
| MC-01 | P0 | ニックネーム、学年、所属キャンパス（瀬田／深草）を登録・表示できる |
| MC-02 | P0 | 「今つくっているもの」を1行で登録・表示できる |
| MC-03 | P0 | 「得意なこと」を登録・表示できる |
| MC-04 | P0 | 「今詰まっていること」を1行で登録・表示できる（空欄可） |
| MC-05 | P1 | 更新するとメンバーボードの先頭に上がる |
| MC-06 | P2 | Discord / GitHub連携でカードを自動更新する |

### 7.2 メンバーボード

| ID | 優先度 | 要件 |
| --- | --- | --- |
| MB-01 | P0 | Horizonの部員全員のカードを一覧表示する（部員以外は登録できない） |
| MB-02 | P0 | 「話したことがある／まだない」を見分けられる |
| MB-03 | P0 | 色だけに頼らず、文字やアイコンでも状態を示す |
| MB-04 | P0 | 所属キャンパスが分かる |
| MB-05 | P1 | キャンパスや技術で絞り込める |
| MB-06 | P2 | 「話したことがない人リスト」としての一括表示（※あえて作らない方針を検討） |

### 7.3 AIによる提案（今日の一人）

| ID | 優先度 | 要件 |
| --- | --- | --- |
| AI-01 | P0 | **部員のうち、まだ話したことがない相手**の中から1人を選ぶ |
| AI-02 | P0 | 新入部員×既存部員の組み合わせと、別キャンパスの相手を優先して選ぶ |
| AI-03 | P0 | 選んだ根拠となる共通点を表示する |
| AI-04 | P0 | 今日できる小さな接点を提案する（オンラインで完結するサイズに限定） |
| AI-05 | P0 | そのまま送れる一言目を生成する |
| AI-06 | P0 | 一言目は本人が確認・編集してから使う。AIは送信しない |
| AI-07 | P1 | 「今日は他の人」でもう1人出せる |
| AI-08 | P1 | 一言目の雰囲気を「気軽」「丁寧」から選べる |
| AI-09 | P2 | 断られた／返信がなかった履歴から提案を調整する |

### 7.4 接点の記録

| ID | 優先度 | 要件 |
| --- | --- | --- |
| RC-01 | P0 | やりとりしたら「話した」を記録できる |
| RC-02 | P0 | 記録するとメンバーボードの表示が「話したことがある」に変わる |
| RC-03 | P0 | 話したことがある人の数を表示する |
| RC-04 | P1 | 何について話したかを1行残せる |
| RC-05 | P2 | 話した相手が増えていく推移を振り返れる |

### 7.5 運営向け

| ID | 優先度 | 要件 |
| --- | --- | --- |
| OP-01 | P2 | サークル全体で、拠点をまたいだ接点が何件生まれたかを見られる |
| OP-02 | P2 | まだ誰とも接点がないメンバーの存在を運営に知らせる |

> 個人の交友関係を一覧にする形では出さない。運営が見るのは全体の傾向まで。

## 8. 画面要件

### モックで必須の3画面

1. **メンバーボード**  
   全員のカード（キャンパス・今つくっているもの・得意・詰まっていること）。
   「話したことがある／まだない」が見分けられる。

2. **今日の一人**  
   AIが選んだ相手、共通点と根拠、今日できる小さな接点、送る一言目。

3. **接点の記録**  
   「話した」を記録する。話したことがある人の数が増える。

### 補助画面

- 自分のカードの登録・編集
- メンバーの詳細カード

補助画面は静的表示でよい。

## 9. AIへの入力と出力

### 入力データ

- 自分のカード（キャンパス、今つくっているもの、得意、詰まっていること）
- 全メンバーのカード
- 自分が「話したことがある」相手のリスト

### 出力例

```text
今日の一人
タクミさん（深草・3年）

共通点と根拠
あなたが詰まっているVite環境構築を、先月同じ構成でやっている

今日できること
30分だけ画面共有して、エラーを一緒に見てもらう

一言目
「はじめまして、瀬田の〇〇です。Viteの環境構築で詰まっていて、
同じ構成をやられていたので、30分だけ見てもらえませんか」
```

### AIがしてはいけないこと

- すでに話したことがある相手を「今日の一人」として出す
- 本人が書いていない情報から共通点を作る
- 移動を前提とした接点を提案する（オンラインで完結しないもの）
- 本人の確認なしにメッセージを送る
- 相性スコアや順位を表示する
- 恋愛的な関係を示唆する文面を作る
- スキルの高低を評価する表現を使う

## 10. 空気・プライバシー要件

- 「今詰まっていること」は空欄を許す。空欄でも共通点は出せるようにする
- 相性スコア・ランキングを出さない。マッチングアプリに見せない
- 「話したことがない人リスト」として晒さない。出すのは常に1人だけ
- 一言目は本人が確認・編集してから送る
- 断られた／返信がないことを記録して見せない
- 運営向けの表示は全体の傾向までにとどめ、個人の交友関係を一覧にしない

## 11. 非機能要件

- スマートフォン縦画面を基準にする
- アプリを開いてから一言目を確認するまで、目標30秒以内
- 一言目はコピーして、そのままDiscordに貼れる
- 状態（話した／まだ）を色だけで示さず、文字やアイコンでも示す
- AIの提案と、本人が登録した事実を見た目で区別する
- モックでは固定データを使い、生成待ちによるデモ失敗を避ける

## 12. MVPの対象外

- DM・チャット機能そのもの（既存のDiscordに渡す）
- ビデオ通話・画面共有機能（既存ツールに渡す）
- イベントの企画、出欠管理
- Discord / GitHub連携、カードの自動更新
- スキルレベルの判定、相性スコアの表示
- 通知・リマインド
- 運営向けの関係マップの可視化
- AIが本人の確認なしにメッセージを送ること

## 13. 受け入れ条件

- [ ] 自分のカード（キャンパス・つくっているもの・得意・詰まっていること）を登録できる
- [ ] メンバーボードで全員のカードが見られる
- [ ] 「話したことがある／まだない」が見分けられる
- [ ] 「今日の一人」に、まだ話したことがない相手が出る
- [ ] すでに話した相手が「今日の一人」に出ない
- [ ] 共通点と根拠が表示される
- [ ] 今日できる接点が、オンラインで完結するサイズで出る
- [ ] 一言目が生成され、確認・編集してから使える
- [ ] 「話した」を記録すると、ボードの表示と人数が変わる
- [ ] 一連のデモを3分のピッチ内で完了できる

## 14. 差別化仮説

> SNSは仲のいい人をさらに推す。このプロダクトは、まだ関わっていない人を推す。

DiscordもイベントもSNSも「場所」を用意しているだけなので、場所を増やしても
もともと話す人がさらに話すだけになる。関係の固定化を崩すには、
**誰と誰が話すべきかを指す役**が要る。そこに、共通点の発見と一言目の生成という
AIでなければ担えない仕事がある。

さらに、接点をオンラインで完結するサイズに限定することで、
瀬田と深草が離れていることが不利でなくなる。

## 15. 未決事項

1. プロダクト名（第1候補：クロス／Cross）
2. 「今日の一人」を出す頻度（毎日／週1／自分で押したとき）
3. 送られた側の画面を作るか
4. 「話した」の記録を、どちらが押すか
5. カードの更新をどう促すか
6. 提案する接点の種類を、どこまでプリセットで持つか

## 16. 制作順

1. 未決事項2〜4をチームで決める
2. デモ用のメンバーカード5〜6人分（瀬田・深草混在）を固定する
3. 必須3画面のラフを作る
4. メンバーボードから「今日の一人」、記録まで画面をつなぐ
5. AI提案は固定出力で先に完成させる
6. 3分ピッチに合わせて操作を通す
7. 余った時間でカード編集画面と見た目を整える
