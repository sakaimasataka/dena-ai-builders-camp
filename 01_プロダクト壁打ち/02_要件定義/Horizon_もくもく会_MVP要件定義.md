# MVP要件定義｜Horizonのもくもく会で「できた」を持ち帰れるようにするアプリ

作成日：2026年8月6日  
用途：AI Builders Camp 京都Kick Off でのモック制作・要件共有  
団体：プログラミングサークル Horizon

## 1. プロダクト概要

### 一言で表すと

> 週1のもくもく会で、来た人が「今日できたこと」と「一緒にやった人」を1つずつ持って帰れるようにするアプリ。

### 解決したい課題

新歓でHorizonに入会した1年生が、週1の対面もくもく会に数回来たあと来なくなる。
来た時点で「今日の2時間で終わるゴール」が決まっておらず、
入門記事の検索と環境構築で2時間が終わり、動くものを何ひとつ持ち帰れないため。
詰まっても誰に聞けばいいか分からず、会が終わっても何も残らないので、次に来る理由が生まれない。

### 提供価値

1. **今日のゴールが決まる**：宣言が2時間で終わるサイズに刻み直される
2. **聞ける相手が決まる**：その日の参加者の中から相棒と声のかけ方が出る
3. **成果が残る**：「できた」が1行残り、次回の出発点になる
4. **離脱に気づける**：誰がいつ来て何が残ったかが運営にも見える

## 2. 想定ユーザー

### 主ユーザー

- Horizonに入会して3か月以内の1年生（プログラミング未経験・初心者）

### 副ユーザー

- 教える側になる既存メンバー
- 離脱に気づけずにいる運営メンバー

### 利用場面

| タイミング | すること |
| --- | --- |
| 会の冒頭5分 | 参加表明と「今日やること」の1行宣言、AI提案の確認 |
| 会の途中 | 詰まったときに相棒を確認して声をかける |
| 終了5分前 | 「できたこと」を1行記録する |
| 次回の冒頭 | 「前回できたこと」から次のゴールを決める |

## 3. 成功の定義

### 最重要指標

**もくもく会に来た人のうち、「できた」を1つ持ち帰った人の割合。**

モック段階では、次の一連の操作を迷わず完了できれば成功とする。

> 参加表明 → 今日やることを1行宣言 → AI提案（ゴール・相棒・声のかけ方）を確認 → 「できた」を記録

### 補助指標

- 「できた」を残した人の翌週の再参加率
- 相棒の提案から実際に会話が発生した割合
- 新歓入会者の3か月後の継続率
- 宣言の入力にかかった秒数（目標15秒以内）

## 4. MVPで証明する仮説

> もくもく会に来た時点で「2時間で終わるゴール」と「聞ける相手」が決まっていれば、
> 初心者でも1回の会で必ず「できた」を1つ持ち帰れて、翌週も来たくなる。

## 5. MVPの基本方針

- スマートフォン縦画面で使うWebアプリとする（会場でその場で開く）
- 宣言の入力は1行・15秒以内で終わる
- AIはゴールを決定せず、刻んだ案を提示してユーザーが確定する
- 相棒の提案は「聞いてもいい人」であって義務ではない
- 「できた」を書かない自由を残す。書かないことを責める表示はしない
- モックでは固定データを使い、生成待ちや通信でデモが止まらないようにする

## 6. デモ用シナリオ

1. 1年生のユーザーAが、水曜19:00のもくもく会に来て参加表明する
2. 今日の参加者一覧に、既存メンバーB・Cの「今日やること」が並んでいる
3. Aが「Reactをやってみたい」と1行だけ宣言する
4. AIが2時間サイズに刻む
   → 「Viteでプロジェクトを作って、ボタンを押すと数字が増える画面まで」
5. AIが相棒を提案する
   → 「Bさん（先月Next.jsで同じ環境構築をやっている）」
   → 声のかけ方「環境構築でつまずいたら聞いてもいいですか」
6. Aが作業して、終了5分前に「できた」に「カウンターが動いた」と記録する
7. 次回の冒頭に「前回できたこと：カウンターが動いた」が表示される

## 7. 機能要件

優先度：P0＝MVP必須、P1＝余裕があれば、P2＝将来。

### 7.1 参加と今日の一覧

| ID | 優先度 | 要件 |
| --- | --- | --- |
| AT-01 | P0 | 今日のもくもく会に参加表明できる |
| AT-02 | P0 | 今日の参加者一覧と、各自の「今日やること」を表示する |
| AT-03 | P1 | 前回の参加履歴と「前回できたこと」を表示する |
| AT-04 | P2 | 出席の自動検知、QRでの入退室管理 |

### 7.2 メンバーカード

| ID | 優先度 | 要件 |
| --- | --- | --- |
| MC-01 | P0 | ニックネーム、学年、得意なこと、学習中のことを登録・表示できる |
| MC-02 | P0 | 今つくっているものを1行で表示できる |
| MC-03 | P1 | 「教えられること」を自分で選んで公開できる |
| MC-04 | P2 | 宣言と「できた」の履歴から得意分野を自動で推定する |

### 7.3 今日やること宣言

| ID | 優先度 | 要件 |
| --- | --- | --- |
| DC-01 | P0 | 「今日やること」を1行で入力できる |
| DC-02 | P0 | 入力は15秒以内で終わる（1画面・1入力欄） |
| DC-03 | P1 | 前回の「できた」の続きをワンタップで引き継げる |
| DC-04 | P1 | 「まだ決まっていない」を選ぶと、AIが候補を出す |

### 7.4 AIによる提案

| ID | 優先度 | 要件 |
| --- | --- | --- |
| AI-01 | P0 | 宣言を、残り時間で終わるサイズのゴールに刻み直す |
| AI-02 | P0 | 今日の参加者の中から、詰まったときに聞くといい相棒を1人提案する |
| AI-03 | P0 | その相棒への声のかけ方を1文で生成する |
| AI-04 | P0 | 提案の根拠を「同じ環境構築をやっている」などの形で表示する |
| AI-05 | P0 | 参加していない人、非公開の情報を提案に使わない |
| AI-06 | P1 | ゴールが大きすぎる／小さすぎるとき、ユーザーが刻み直しを依頼できる |
| AI-07 | P2 | 過去の「できた」の履歴から、次のゴールを個人化する |

### 7.5 「できた」の記録

| ID | 優先度 | 要件 |
| --- | --- | --- |
| DN-01 | P0 | 終了時に「できたこと」を1行記録できる |
| DN-02 | P0 | 記録した「できた」を今日の一覧に表示する |
| DN-03 | P0 | 次回の冒頭に「前回できたこと」を表示する |
| DN-04 | P1 | できなかった場合に「途中まで」を残せる |
| DN-05 | P1 | 誰に助けてもらったかを記録できる（教える側にも残る） |
| DN-06 | P2 | 「できた」の積み上げを時系列で振り返れる |

### 7.6 運営向け

| ID | 優先度 | 要件 |
| --- | --- | --- |
| OP-01 | P1 | 参加者と「できた」の記録が一覧で見られる |
| OP-02 | P2 | 2回連続で来ていない人を運営に知らせる |
| OP-03 | P2 | 「できた」が続けて0の人を運営に知らせる |

## 8. 画面要件

### モックで必須の3画面

1. **今日のもくもく会**  
   参加表明ボタン、今日の参加者一覧、各自の「今日やること」。

2. **今日やること入力／自分のカード**  
   1行の入力欄。あわせて得意・学習中・今つくっているもの。

3. **AI提案 →「できた」記録**  
   今日のゴール、今日の相棒、声のかけ方、根拠。会の終わりに「できた」を1行記録するところまで。

### 補助画面

- メンバーカードの登録・編集
- 過去の「できた」一覧

補助画面は静的表示でよい。

## 9. AIへの入力と出力

### 入力データ

- 本人の宣言（1行）、得意なこと、学習中のこと
- 今日の参加者の宣言と、公開されている得意分野
- 残り時間

### 出力例

```text
今日のゴール
Viteでプロジェクトを作って、ボタンを押すと数字が増える画面まで

今日の相棒
タクミさん（3年）

根拠
先月、同じViteの環境構築をやっている

声のかけ方
「環境構築でつまずいたら聞いてもいいですか」
```

### AIがしてはいけないこと

- 今日参加していない人を相棒として提案する
- 本人が公開していない情報（詰まっている内容、過去の失敗）を他人に見せる
- 2時間で終わらないサイズのゴールを「今日のゴール」として出す
- 本人の確認なしにメッセージを送る
- スキルの高低を評価・順位づけして表示する
- 「できた」が書けなかったことを責める文言を出す

## 10. プライバシー・空気の要件

- 宣言は「今日やること」であって進捗報告ではない。遅れを晒す形にしない
- 相棒の提案は義務ではなく、教える側にも断る導線を置く
- 「できた」を書かない自由を残す
- 運営向けの表示は、本実装で「来ていない人リスト」のような形にしない
- 監視ではなく本人の役に立つ機能であることが、画面上で分かるようにする

## 11. 非機能要件

- スマートフォン縦画面を基準にする
- 参加表明から宣言完了まで、目標30秒以内
- AI提案の表示まで、目標10秒以内
- 会場のWi-Fiが不安定でも、宣言の入力だけは完了できる
- AIの提案と、事実として登録された情報を見た目で区別する
- モックでは固定データを使い、生成待ちによるデモ失敗を避ける

## 12. MVPの対象外

- 出席の自動検知、GPS、QRでの入退室管理
- Discord / GitHub連携、コミットの自動取得
- スキルレベルの判定、長期のスキルマップ
- 運営向けの離脱アラートダッシュボード
- 通知・リマインド
- 3人以上のチーム分けの自動最適化
- AIが本人の確認なしにメッセージを送ること
- 過去の記録の長期集計とグラフ

## 13. 受け入れ条件

- [ ] 今日のもくもく会に参加表明できる
- [ ] 今日の参加者と、各自の「今日やること」が一覧で見える
- [ ] 「今日やること」を1行で入力できる
- [ ] AIが2時間で終わるサイズのゴールを出す
- [ ] AIが今日の参加者の中から相棒と声のかけ方を出す
- [ ] 提案の根拠が表示される
- [ ] 「できた」を1行記録できる
- [ ] 記録した「できた」が一覧に反映される
- [ ] 参加していない人が相棒として出ない
- [ ] 一連のデモを3分のピッチ内で完了できる

## 14. 差別化仮説

> その日その場にいる人の宣言と得意分野を突き合わせて、
> 2時間で終わるゴールと聞ける相手を同時に出す。

告知ツール（Discord）は来るまで、出席簿（Notion）は記録まで、ChatGPTはその場の人を知らない。
この3つの隙間が、そのまま新入生が黙って2時間を溶かす場所になっている。

## 15. 未決事項

1. プロダクト名（第1候補：できた／Dekita）
2. 宣言を毎回書かせるか、前回の続きをデフォルトにするか
3. 相棒を1人に絞るか、複数候補を出すか
4. 「できた」が書けなかった日の扱い
5. 得意分野を初回入力にするか、履歴から推定するか
6. 運営向けの可視化をどの段階から入れるか

## 16. 制作順

1. 未決事項2〜4をチームで決める
2. デモ用の参加者3〜5人分（宣言・得意分野）を固定する
3. 必須3画面のラフを作る
4. 参加表明から「できた」記録まで画面をつなぐ
5. AI提案は固定出力で先に完成させる
6. 3分ピッチに合わせて操作を通す
7. 余った時間で見た目とメンバーカードを整える
